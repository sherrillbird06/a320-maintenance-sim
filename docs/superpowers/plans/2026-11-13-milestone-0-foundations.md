# Milestone 0 — Foundations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deployed, tested, empty-but-real project: toolchain, data schemas, the full component registry, cited sources, the Blender-to-browser asset pipeline, budgets, and a look test that proves the rendering quality.

**Architecture:** Static site. Vite + React + TypeScript, three.js through React Three Fiber. All content is typed data validated by Zod; pure logic lives apart from rendering. Models are generated by Blender Python scripts run headless, exported as glTF and optimized with glTF-Transform.

**Tech Stack:** Node 26, Vite 8, React 19, TypeScript 7 (strict), three 0.187, @react-three/fiber 9, @react-three/drei 10, Zod 4, Vitest 5, Playwright 1.65, ESLint 10, Prettier 3, glTF-Transform 4, Blender 5.2 (headless).

**Spec:** `docs/superpowers/specs/2026-11-13-a320-maintenance-sim-design.md`

This plan covers Milestone 0 only. Each later milestone gets its own plan when it starts.

## Global Constraints

- No invented torque values, tolerances, quantities, intervals or limits anywhere — code, data, docs, or test fixtures.
- Every aircraft fact in data names a source id from `src/data/sources.ts`. Unverifiable facts are left out.
- Nothing is copied from the Scribd AMM document.
- Banner text, exact: `Training simulation — not approved maintenance data`.
- No real American Airlines wordmark or logo. Registration, MSN and work-order numbers are fictional.
- Third-party assets are CC0 only, each listed in `docs/sources.md` with its URL.
- Own code is MIT.
- Component ids match `^[a-z0-9]+(_[a-z0-9]+)*$` and equal the glTF node name.
- Budgets: first load ≤ 40 MB, exterior ≤ 400,000 triangles, cockpit ≤ 150,000, hangar ≤ 200,000, target 60 fps.
- Desktop only (keyboard and mouse).
- The site must work from a sub-path (`/a320-maintenance-sim/`).
- TypeScript strict; no `any`; ESLint and Prettier clean.

## Review Focus

1. WebGL2 unavailable → a readable message, not a blank page. (Task 1)
2. Served from a sub-path → every asset URL resolves. (Tasks 1, 7)
3. A model or texture fails to load → an error panel naming the file. (Task 5)
4. Touch-only or narrow device → a "desktop required" notice. (Task 1)
5. A registry record with a duplicate id, malformed id, or unknown ATA chapter/zone/source → validation fails naming the record. (Task 2)

### Task 5: Asset pipeline

**Files:** Create `assets-src/blender/common.py`, `assets-src/blender/lookdev_tire.py`, `assets-src/build_models.mjs`, `scripts/check-models.mjs`, `src/world/loadModel.ts`. Test: `tests/unit/checkModels.test.ts`, `tests/unit/loadModel.test.ts`.

**Interfaces — Produces:**
- `npm run models` → runs each Blender script headless (`blender.exe --background --python <script> -- --out <tmp.glb>`), then glTF-Transform (dedup, prune, meshopt, WebP textures) into `public/models/<name>.glb`. Blender path from `BLENDER` env, default `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`. Generated `.glb` files are committed so CI needs no Blender.
- `checkModels({ nodeNames: string[]; inspectableNodes: string[]; componentIds: string[]; model: 'exterior' | 'cockpit' }): string[]` — a problem per registry id with no node, and per node marked `extras.inspectable` with no record. `npm run check:models` applies it to each model file that exists; a model not yet built is reported as "pending", not an error.
- `modelUrl(name: string): string` — respects the Vite base path. `describeLoadError(url: string, err: unknown): { title: string; body: string }` — body names the file.

- [ ] Step 1: Write tests for `checkModels` (missing node, unregistered inspectable node, clean case) and `describeLoadError` / `modelUrl` with a base of `/a320-maintenance-sim/`.
- [ ] Step 2: Implement. Write the tire script: an aircraft main-wheel tire and wheel at real size, grooved tread, node names `lookdev_tire` and `lookdev_wheel`.
